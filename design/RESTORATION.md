# Mobile v2 还原与验收说明

基准：Stitch 项目 `10181264019524647663`，以及用户导出的 36 张 390 × 844 页面截图。导出中仅 00 系列包含 HTML，其余页面按完整尺寸 PNG 核对。

## 视觉规格

| 项目 | 实现 |
| --- | --- |
| 页面 | #F7F7F4，左右 20px，顶部预留系统栏空间 |
| 品牌主色 | #245C4F；登录 #1F4D3A；注册 #275945 |
| 卡片 | 白色，浅边框，20px 主圆角；登录 28px、注册 22px |
| 首页 | 36px 余额数字，按日期合并流水，固定底部四页签 |
| 账户 | 轻量账户图标、计入状态、20px 个人余额、搜索与隐藏金额 |
| 表单 | 64px 左右的表单行、底部固定保存区、独立类型选择弹窗 |
| 数字键盘 | 三列数字、右侧删除及跨行确定；两位小数校验 |
| 健康 | 成员列表、实际记录折线图、独立底部体重弹窗 |
| 动效 | 按压反馈、选项状态过渡、弹窗进入；尊重减少动态效果设置 |

## 页面版本处理

遵循原功能说明：同功能以更高序号版本优先。年度统计以 28 的年度分类和月度明细版实现；21 的过程版本在对照工具中映射到当前年度页。22 的收支结余通过统计更多菜单进入。

设计图里的模拟 iOS 时间及 Home Indicator 不画入 Android 页面，使用设备真实系统栏。资产金额和统计图表取实际本机记录，因此内容不会与设计样例数值逐像素一致。

## 验收方式

1. `tools/review.html` 同屏显示原稿与可操作的实现，逐页核对。
2. `tests/browser-audit.html` 覆盖 36 页 × 320/390/430px，检查页面渲染、运行错误与水平溢出。
3. 交互回归涵盖数字精度、表单保留、账目入账、账户类型、分类配色、返回层级、体重弹窗、搜索、日历和登录校验。
4. Node 回归检查记账规则、金额边界、分精度、汇总一致性和本机保存恢复。
5. Android 执行 assembleDebug 与 lintDebug，并在连接的模拟器安装启动。固定竖屏是沿用项目的产品设定，lint 对多窗口/横屏兼容性有两项提示。

这些检查验证功能与版式约束，不等同于全屏自动像素一致率测试。字体映射、原始数据差异和缺少交互规格的部分详见根目录 README。
